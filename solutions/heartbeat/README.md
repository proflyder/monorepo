# heartbeat — внешний dead-man switch

Cloudflare Worker для контроля живости домашнего контура. Alertmanager
отправляет всегда горящий `Watchdog` на `/ping`; Worker запоминает время
последнего сигнала. Cron Trigger проверяет тишину и при пропуске дольше
grace-периода пишет в Telegram через **тот же инфра-бот**, что и Alertmanager.
Когда сигналы возвращаются — приходит сообщение о восстановлении.

Решение не знает о конкретном доме, DNS, namespace или чате: всё приходит
через `env` конкретного проекта. Реализация — plain JavaScript ES modules,
без npm-зависимостей и сборки, только Workers runtime.

## Контракт

| Запрос | Ответ |
|---|---|
| `GET /health` | `200 ok`, без auth, без раскрытия состояния |
| `POST /ping` | `200 ok`; требует `Authorization: Bearer <PING_TOKEN>` |
| любой другой путь/метод | `404` |
| неверный/отсутствующий токен | `401` |
| `PING_TOKEN` не задан | `503` (fail closed) |

Тело `/ping` — стандартный Alertmanager webhook JSON. Полезная нагрузка не
разбирается, кроме одного случая: `{"status":"resolved"}` подтверждается
`200`, но **не** считается признаком жизни.

`GET /health` намеренно не отдаёт состояние: это только проверка, что Worker
развёрнут и отвечает.

## Состояние в Workers KV

| Ключ | Значение |
|---|---|
| `last_ping_unix` | время последнего принятого ping, Unix seconds |
| `state` | `up` или `down` |
| `down_since_unix` | время последнего ping перед уходом в `down` |
| `last_reminder_unix` | время последнего сообщения/напоминания |

Каждый ping делает одну запись `last_ping_unix`. Состояние пишется только при
переходе `up → down` или `down → up`. При пинге раз в 5 минут это ≈288
записей в сутки; бесплатный план Workers KV допускает 1000 записей в сутки,
запас более чем втрое. Чтения и удаления в лимит записей не входят.

## Конфигурация

Vars (`wrangler.toml`):

| Переменная | По умолчанию | Смысл |
|---|---|---|
| `GRACE_SECONDS` | `900` | сколько тишины терпеть до алерта |
| `REMIND_SECONDS` | `21600` | напоминание, пока состояние `down`; `0` — выключить |
| `SITE_NAME` | `дом` | имя в тексте Telegram |

Secrets (только через `wrangler secret put`):

| Secret | Назначение |
|---|---|
| `PING_TOKEN` | bearer-токен для `/ping` |
| `TELEGRAM_BOT_TOKEN` | токен инфра-бота |
| `TELEGRAM_CHAT_ID` | чат владельца |

Тексты сообщений — русские, `parse_mode: HTML`; `SITE_NAME` экранируется.

## Поведение

- Первый запуск: пока не было ни одного ping, cron молчит. Иначе свежий
  деплой сразу отправил бы ложный алерт.
- `decidePing`: ping во время `down` → сообщение «связь восстановлена» и
  переход в `up`.
- `decideCron`: тишина больше `GRACE_SECONDS` → «дом молчит N минут: нет
  heartbeat от Alertmanager (питание/интернет/Proxmox/K3s/Alertmanager)» и
  переход в `down`.
- Пока `down`, повторное сообщение не чаще `REMIND_SECONDS`.
- Если Telegram недоступен, состояние не меняется и следующий cron
  повторяет попытку. При сбое отправки recovery Alertmanager получает `502`
  и повторяет ping. Возможен один дубликат сообщения при сбое записи KV —
  это осознанный выбор в пользу at-least-once.

## Тесты

Тесты используют встроенный `node:test` и не требуют npm:

```bash
node --test solutions/heartbeat/src/*.test.js
```

Проверяются чистые решения `decidePing`/`decideCron`, разбор payload,
constant-time сравнение токена, маршруты `/ping` и `/health`, запись KV,
отправка Telegram и поведение при сбое доставки. KV и `fetch` замоканы.
