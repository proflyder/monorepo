Неттоп lab-host: i7-12650H, 16 GB RAM (около 14 GiB ОС), дискретный GPU не указан. Ubuntu, HA Container 2026.10.4, сеть HA host. IP `.26` Ethernet, `.25` Wi-Fi. Станция `.13`.

Прочитаны: README, STATE, INVENTORY, старое TTS-исследование, Hermes README и `voice_proxy.py`, `nettop/stack/docker-compose.yml`, alarm section в `nettop/ha-voice/scripts.yaml`, tts-lab и состав сэмплов.

Важные ограничения:

- В `alarm_announce` отдельный `tts.speak` → `tts.piper`. Изменение только Assist pipeline не меняет голос будильника.
- Сохранить `media_player.iandeks_stantsiia_midi_media_player` для alarm speech/chime; universal MA endpoint может нарушить source/resume Spotify.
- Таймеры/будильники/громкость должны оставаться независимыми от Hermes.
- Hermes proxy принудительно выставляет `stream=false`, очищает полный JSON. В первом TTS-релизе не переделывать его на streaming.
- HA Wyoming 2026.10.4 имеет обычный буферизующий WAV-путь и отдельный streaming-путь. AudioChunk сам по себе не доказывает раннее слышимое воспроизведение.
- Watchdog responding через 25 секунд — не способ лечить медленный синтез.

Живой доступ: SSH `.26` timeout; `.25` ответил, но BatchMode-аутентификация не прошла. **Не утверждать, что сервер выключен или что требуется конкретный пароль:** это только результат этих попыток. ## 6. Техническое направление следующей реализации

1. Восстановить рабочий доступ; перечитать live hardware/load и HA pipeline. Сделать backup по правилам проекта.
2. Поднять Silero v5_6_ru/eugene отдельным сервисом рядом с Piper. Предложенный внешний endpoint — localhost:10209; проверить, свободен ли порт.
3. Оценить `staastas/wyoming-silero`: community-код, не официальный продукт Silero. Закрепить commit/digest, проверить модель и speaker, прогрев, offline restart. Готовность обёртки не означает готовый RUAccent frontend.
4. Добавить RUAccent перед apply_tts с правильной разметкой ударений и словарём. Обязательно воспроизвести показанный вариант; проверить взаимодействие внешней разметки со встроенными put_accent/put_yo/омографами на конкретной версии, не предполагать нужные флаги без чтения API.
5. Обработку размещать на стороне TTS, чтобы её получали local intents, Hermes и tts.speak. Один патч Hermes-proxy этого не обеспечивает.
6. Создать тестовый pipeline, менять только TTS. Протестировать корпус, затем реальную станцию.
7. Отдельно перенести alarm speech; для постоянной wake-фразы разумен заранее сгенерированный локальный WAV. Chime должен работать при падении TTS.
8. Piper оставить для отката. Автоматического fallback Assist от наличия второго контейнера не появляется: router — отдельная реализация, если нужен.
9. После приёмки переключить основной pipeline, обновить STATE/HISTORY/PENDING и проверить source/volume restore, stop/snooze и resume музыки.

Порог из плана: warm p95 слышимого начала после готового текста в HA ≤1.5 с для обычных коротких ответов, желательная цель ≤0.8 с. Это **предлагаемые цели, не замеренные результаты**. CPU threads 2/4 — варианты эксперимента. Не обещать задержку по Mac или статье.

## 7. Перепроверенные факты исследования

- Silero v5_6_ru имеет Eugene и встроенную обработку ударений/омографов. Веса RU — CC BY-NC 4.0; не переносить MIT-лицензию CIS на них.
- CIS base/nostress — MIT, но для русского требуют отдельно подготовленных ударений. `_nostress` не значит auto-stress.
- Qwen3-TTS нельзя называть CUDA-only: актуальный llama.cpp документирует TTS Base с русским и reference. Это не доказанный realtime на i7 и не готовый Wyoming.
- MOSS-TTS-Nano ONNX — интересный CPU-клоновый путь, но пользователь уже выбрал готовый Eugene; эту ветку сейчас не развивать.
- Supertonic 3 поддерживает RU, но upstream архивирован; не предлагать как основной сопровождаемый путь.
- 48 kHz не является доказательством лучшего качества. ASR WER не измеряет приятность и может не замечать неверных ударений.

Первоисточники и сравнение альтернатив находятся в полном исследовании. Никаких гарантий «идеальные ударения на любом тексте» пользователю не давалось.
