# Дополнительный поиск голосов после прослушивания Piper

> **Итог выбора и внедрения:** пользователь выбрал Puriso; он установлен и проверен с текущим Piper. Подробности — [DEPLOY-RICARDO-PURISO.md](DEPLOY-RICARDO-PURISO.md). Ниже сохранены ход поиска и его исходные ограничения.

27 октября 2026. Уточнение пользователя: «пайпер идеально делает речь... только сам голос мне не нравится... силеро конечно прикольный вариант, но может поищешь еще?»

Это меняет приоритет: не считать Silero Eugene окончательным решением. Он остаётся ранее понравившимся кандидатом, но пользователь открыл поиск заново. Kokoro по-прежнему исключён. Предпочтение — сохранить понравившиеся произношение/подачу Piper и найти другой мужской тембр.

## Новые кандидаты и проверка

### 1. Puriso — дополнительный мужской голос для Piper

Первоисточник: https://huggingface.co/dhammagift/piper-ru-puriso

Веса `ru_puriso2-medium.onnx` — 63 516 051 байт, 22 050 Hz. Это отдельный community checkpoint; он не входил в показанные ранее Denis/Dmitri/Ruslan. Автор описывает fine-tuning Ruslan на русском синтетическом корпусе Supertonic M1. То есть это новый тембр внутри Piper, а не обязательный переход на Supertonic runtime.

Автор указывает совместное применение CC BY-NC-SA 4.0 и OpenRAIL-M. Нельзя описывать веса как MIT/Apache. Ударения учебного корпуса не гарантируют произношение любого нового слова.

Для проекта это самый прямой новый кандидат: проверить файл и его config с текущей версией Wyoming Piper, затем выбрать его в тестовом pipeline. На этапе поиска совместимость ещё не была проверена; последующее успешное внедрение зафиксировано в deploy-документе.

### 2. UtrobinTTS high multispeaker — мужской speaker_id=1

Первоисточник: https://huggingface.co/utrobinmv/tts_ru_free_hf_vits_high_multispeaker

Русская VITS-модель: женский и мужской speaker. Карточка — Apache-2.0. Наш скачанный safetensors — 159 690 732 байта. В конфигурации sample rate 16 000 Hz; слово high в имени не означает 48 kHz и не доказывает субъективное качество.

Автор поддерживает CPU и рекомендует внешний акцентуатор для улучшения ударений. Ниже тестировался native lowercase frontend без RUAccent. Подключение к Assist потребует собственного адаптера или отдельно проверенного экспорта; это не готовая замена ONNX-файла Piper.

### 3. Vosk TTS — дополнительная ветка, без нового локального синтеза

Первоисточники: https://github.com/alphacep/vosk-tts и https://huggingface.co/alphacep/vosk-tts-ru-multi

Есть русская multispeaker-модель с двумя мужскими голосами. В показанной карточке HF — checkpoint 0.7, текущий README runtime приводит 0.9: не смешивать их speaker IDs и результаты. В этой сессии веса Vosk не запускались. Кандидат для следующего сравнения, если два новых сэмпла не понравятся.

### 4. Собственный голос Piper — направление при сохранении любимого движка

Официальное обучение: https://github.com/OHF-Voice/piper1-gpl/blob/main/docs/TRAINING.md

Можно дообучить Piper на подходящем мужском голосе и экспортировать ONNX. Существование Puriso показывает практическую реализацию синтетического teacher→Piper пути, но не доказывает сохранение всех интонаций/ударений исходного голоса или произвольный тембр без данных и обучения. Нужны качественные данные, транскрипты, права использования, тренировочный эксперимент и приёмка; выбор GPU/стоимости после оценки данных. Это перспективнее, чем бесконечно менять движки, если пользователь ценит именно текущий Piper.

Piper → voice conversion (RVC/OpenVoice и аналоги) тоже возможно исследовать, но дополнительная ступень может ухудшить дикцию и увеличить задержку. В этой сессии не запускалась и не предлагается как уже готовое решение.

## Что отвергнуто на этапе проверки

Audio8 0.1B ONNX INT8 сначала выглядел подходящим по CPU-размеру, но его текущая официальная карточка рекомендует 11 языков без русского. Поэтому в RU shortlist он не включён: https://huggingface.co/Edge0/audio8-TTS-0.1B-ONNX-INT8 . Не выдавать multilingual за подтверждённый RU.

`splastunov/piper-ru` содержит Kuza.onnx, но не имеет содержательной карточки/проверенного происхождения голоса. Для текущей рекомендации данных недостаточно; не выдавался пользователю как проверенный дополнительный тембр.

## Новые локальные примеры

Синтез выполнен на Mac через уже имевшееся окружение `/private/tmp/ttsenv`. Его состав не менялся. Использовались локально скачанные ONNX/Safetensors, сторонний remote code не исполнялся. Это **не** замеры на lab-host и **не** слуховая оценка агентом.

На каждый кандидат созданы short/long/stress:

- short: «Привет! Я Рикардо. Чем могу помочь?»
- long: «Сейчас в Москве плюс двадцать три градуса, небольшой ветер. Будильник на семь тридцать установлен.»
- stress: «Мне звонят из аэропорта. На двери висит замок, а на горе стоит старинный замок. В каталоге появился новый альбом.»

Puriso: штатный frontend Piper/espeak, без пользовательских поправок ударений. Utrobin: lowercase plain text, speaker_id=1, CPU, seed 555, без RUAccent. Файлы проверены на читаемость, конечные ненулевые отсчёты, длительность и уровень. Эти проверки не доказывают правильное произношение; требуется прослушивание пользователя.

Сэмплы и `manifest.json` в проекте: `artifacts/tts-research-2026-10-27/voice-samples/`. В manifest сохранены точные revisions моделей, тексты, форматы, времена на Mac и хеши аудио. Скрипт генерации и source README — рядом в `reproduction/` (веса не копировались в проект).

На момент первоначальной записи этого поиска голоса ещё не были приняты и live-контур не менялся. Позже пользователь выбрал Puriso и разрешил его внедрение; результат — в DEPLOY-RICARDO-PURISO.md. ZIP проекта от 26 октября остаётся прежним снимком и не содержит эти материалы.
