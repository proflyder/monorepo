# План: будильники, таймеры, напоминания и заметки

Статус: **реализовано 2026-10-27; идёт живая приёмка**. Владелец поведения:
`projects/home-assistant/ha-voice/`; канонический runtime — HA на `lab-host`.

## 1. Цель

Заменить один YAML-слот будильника и непрозрачные Assist-таймеры на
управляемые списки, которые можно создавать, редактировать и удалять из
приложения HA и голосом «Рикардо».

Границы:

- источник истины — Home Assistant, без синхронизации с нативным
  приложением Яндекс/Алисой;
- нативные будильники станции HA не видит и не меняет;
- текущий проверенный путь звонка на Pulsar сохранён: непрерывный
  локальный рингтон + ramp, stop/snooze, restore source/volume, resume
  музыки; Puriso TTS остаётся для announce/таймеров/напоминаний;
- без HACS-интеграции будильника в качестве основной зависимости;
- без ручного редактирования `.storage`.

## 2. Итоговое решение

| Объект | Хранилище | UI | Голос |
|---|---|---|---|
| Будильники | `local_todo`, 4 списка по режиму повтора | to-do card / custom card | создать, список, изменить, удалить, вкл/выкл |
| Таймеры | пул нативных `timer` helpers + labels | entities/timer cards | старт, список, пауза, продолжение, отмена, +время |
| Напоминания | `local_todo.reminders` с `due_datetime` | to-do card | создать, список, выполнить, удалить |
| Заметки | `local_todo.notes` без времени | to-do card | создать, найти, удалить |

### Будильники

Списки:

```text
todo.alarms_once       — однократные
todo.alarms_daily      — каждый день
todo.alarms_weekdays   — по будням
todo.alarms_weekends   — по выходным
```

Элемент списка:

```text
summary        — название («Работа», «Выходной»)
due_datetime   — ближайшее срабатывание
status         — needs_action = включён, completed = выключен
description    — опционально: громкость, служебные метаданные
```

Планировщик читает `todo.get_items` каждые 30 секунд и на старте HA.
После звонка:

- однократный — `completed`;
- ежедневный — следующая дата `+1 день`;
- будни/выходные — следующая подходящая дата;
- при простое HA — звонок только в пределах grace-окна 10 минут, иначе
  перенос; просроченный однократный не звонит.

Одновременно звонит один будильник. Остальные при совпадении времени
становятся в очередь. Snooze — 9 минут, глобальный `alarm_snooze_until` +
uid текущего элемента.

### Таймеры

8 UI-created `timer` helpers с `restore: true` и label `assistant_timer`.
У каждого companion `input_text` для названия. Голосовой интент выбирает
первый `idle` timer; `paused` можно продолжить; `active` можно отменить.
`timer.finished` озвучивается на Pulsar. При старте HA проверяются
просроченные/восстановленные таймеры.

Ограничение MVP: пул фиксированный. Динамический `timer_list` — отдельная
будущая задача после появления его в HA core или custom-интеграции.

### Напоминания и заметки

`local_todo.reminders` — `due_datetime`, уведомление на Pulsar и телефон;
`local_todo.notes` — без времени, голосовой CRUD и поиск по тексту.
Семантический поиск через Hermes — опция, не блокер MVP.

## 3. Голосовое управление

Все фразы — русские custom sentences + `intent_script`; локальные интенты
имеют приоритет над Hermes. Ответы короткие, TTS-friendly.

### Будильники

```text
поставь будильник на 7:30
поставь будильник на 7:30 на завтра
поставь будильник на 7:30 по будням
поставь будильник на 9:00 по выходным
поставь будильник на 7:30 каждый день
поставь будильник «работа» на 7:30 по будням
поставь будильник через 20 минут
заведи будильник через 2 часа
поставь будильник работа через 30 минут
какие будильники
какой будильник
включи будильник на 7:30
выключи будильник на 7:30
измени будильник на 7:30 на 8:00
измени будильник работа на 8:45
включи будильник работа
удали будильник на 7:30
удали все будильники
отложи будильник
останови будильник
стоп
```

### Таймеры

```text
поставь таймер на 5 минут
поставь таймер на одну минуту
поставь таймер «пицца» на 10 минут
какие таймеры
сколько осталось на таймере «пицца»
поставь таймер «пицца» на паузу
продолжи таймер «пицца»
добавь 2 минуты к таймеру «пицца»
отмени таймер «пицца»
отмени все таймеры
```

### Напоминания

```text
напомни завтра в 9:00 позвонить
напомни через 2 часа проверить духовку
какие напоминания
что у меня на сегодня
выполнил напоминание про звонок
удали напоминание про звонок
```

### Заметки

```text
запомни, что ...
что я записал про ...
покажи заметки
удали заметку про ...
```

Если фраза не распознана, Assist отвечает подсказкой; Hermes не должен
создавать/удалять будильники в обход локальных интентов.

## 4. UI

- Dashboard «Помощник»: to-do cards будильников, напоминаний, заметок;
  timer cards; ближайший будильник/таймер.
- На вкладке будильников — форма «название + время + повтор»; due-дата
  следующего звонка рассчитывается скриптом, а не вводится как дедлайн.
- MVP использует штатные to-do/timer cards. Если штатная to-do card не
  позволяет удобно задать время/повтор — добавляется тонкая custom card,
  без изменения backend.
- Внутренние helpers (если останутся на переходный период) скрываются;
  старый `input_datetime.alarm_next` после приёмки удаляется из YAML.

## 5. Фазы (выполнено)

1. **Backup + scaffold.** Снимок HA config; создать local_todo списки,
   8 timer helpers, labels, dashboard. Старый будильник не трогать.
2. **Alarm engine.** Scheduler, перенос звонка на элементы списка, повторы,
   snooze/stop/restore, startup/DST, голосовые интенты будильников.
3. **Timers.** Пул, labels, голосовые интенты, finished TTS, restart.
4. **Reminders/notes.** local_todo, scheduler, TTS/phone, голосовой CRUD.
5. **UI + docs + приёмка.** Dashboard, custom card при необходимости,
   `STATE`/`OPERATIONS`/`PENDING`/`HISTORY`, backup, отключение старого слота.

## 6. Приёмка

- 3 будильника (однократный, ежедневный, будни) создаются в UI, видны,
  редактируются и удаляются.
- Голосом: создать, перечислить, изменить время, выключить, удалить.
- 3 таймера одновременно; UI показывает active/paused; pause/resume/cancel.
- После restart: будильники и таймеры сохраняются; просроченные
  обрабатываются по grace-окну.
- Звонок на Pulsar, stop/snooze, restore source/volume, resume Spotify.
- Напоминание приходит на Pulsar и телефон; заметка создаётся/находится.
- `hass --script check_config` RC=0; нет failed units; remote access не
  затронут.
- Нативные будильники Яндекса не синхронизируются — это записано в docs.

## 7. Откат

До приёмки старые `alarm_*` scripts, helpers и `alarm_scheduler` остаются в
конфиге, но новый scheduler включается отдельно. При ошибке:

1. выключить новый scheduler;
2. вернуть старый `alarm_scheduler` и YAML-хелперы из backup;
3. reload automations/scripts, проверить `alarm_ringing=off`, restore
   source/volume;
4. не откатывать `.storage` целиком без необходимости.

## 8. Ресерч-основания

- HA Timer: несколько сущностей, `restore`, но `timer.finished` не
  срабатывает, если HA лежал в момент окончания.
- Assist timers: несколько именованных, но не entities, не видны в UI,
  теряются после restart.
- `local_todo`: динамические элементы, UI CRUD, `due_datetime`, описание,
  статусы; сервисы add/get/update/remove.
- `local_calendar`: UI recurrence, но сервисы только create/get; нет
  update/delete для голосового CRUD.
- `timer_list`: архитектура одобрена HA core 2026-09-03, в 2026.10.4 ещё
  не поставлена; поэтому MVP — пул `timer`.
- HACS-варианты (Wakey, HA-Alarm-Clock, HA-Alarms-and-Reminders, Kobold)
  изучены, но для критичного пробуждения не выбраны основными: новый код,
  beta, English/German voice, media-player path, нет Puriso/chime/resume.
  Wakey — возможный пилот после MVP, со старым будильником как страховкой.
