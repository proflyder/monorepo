# pulsar

Яндекс Станция Миди, Лайт 2, Мини 2, Мини 3 и Мини первого поколения как локальный голосовой
спутник и умная колонка для [Home Assistant](https://www.home-assistant.io/) — без облака Яндекса.

| Модель | Кодовое имя | Статус | Данные о модели |
|---|---|---|---|
| Станция Миди | `cucumber` | проверена мейнтейнером | станция мейнтейнера |
| Станция Лайт 2 | `plum` | проверена мейнтейнером | станция мейнтейнера |
| Станция Мини 2 | `station-mini2` | экспериментально, см. [Мини 2](#мини-2) | контрибьюторы: [#9](https://github.com/Morvex885/pulsar/pull/9), станция из [#38](https://github.com/Morvex885/pulsar/issues/38) |
| Станция Мини 3 | `bergamot` | экспериментально, см. [профиль](https://github.com/Morvex885/pulsar/blob/main/docs/mini3.md) | контрибьютор: [#30](https://github.com/Morvex885/pulsar/pull/30) |
| Станция Мини | `yandexmini` | по данным контрибьютора, см. [Мини](#мини) | контрибьютор: [#35](https://github.com/Morvex885/pulsar/pull/35) |

> **Ricardo fork:** этот checkout — отдельный Rust-профиль для нашей Midi.
> База — upstream `v0.6.2` (ранее `v0.6.1` и `v0.5.4`); на колонке стоят релизы
> форка `v0.5.10NN`, далее вычисляемые `v0.6.NNN` (см. `RICARDO.md`).
> Из upstream `v0.6.2` взяты переключатели «Wake sound» и «Clock colon blink»
> (`wake_sound` / `clock_colon_blink` в `state.conf`) и окно локальных команд
> только для диалога от wake word (#61); стоп-слова из текста STT в форке
> обрабатываются по-своему (см. ниже и `RICARDO.md`). Ключи этих сущностей —
> 42/43, потому что upstream-ключи 39/40 заняты «Follow-up duration» и
> «Громкость объявлений».
> Отличия, сборка и границы приёмки — [`RICARDO.md`](RICARDO.md).

Вместо штатного стека Яндекса (`maind`) на колонке работает небольшой нативный демон. Он говорит с
Home Assistant по протоколу ESPHome Native API и выглядит в HA как обычное ESPHome-устройство.
Для [Music Assistant](https://music-assistant.io/) он дополнительно является нативным
[Sendspin](https://www.sendspin-audio.com/)-плеером.

Железо колонки используется полностью и штатными средствами прошивки:

- **«Алиса» / «Яндекс»** — родная модель активационной фразы Яндекса и родное
  шумоподавление/эхоподавление (VQE) по микрофонам колонки (Миди — 4, Лайт 2 — 2, Мини 2 — 4,
  Мини 3 — 3, Мини — 4) с вычитанием звука собственных динамиков.
- **Локальные голосовые команды** — «стоп», «громче», «тише», «продолжи» и т. д. выполняются на
  самой колонке, без HA и без «Алиса» (родная модель команд Яндекса).
- **Отвечает ближайшая колонка** — если «Алису» услышали несколько колонок с pulsar, отвечает та,
  что услышала громче.
- **Динамики** — воспроизведение HTTP-потоков через GStreamer прошивки, громкость через ALSA.
- **Кольцо светодиодов, часы, кнопки, переключатель микрофона, датчик освещённости** — по моделям;
  у Мини нет части из них (см. [Мини](#мини)).
- **Zigbee (Миди, экспериментально)** — встроенный Zigbee-модуль колонки на собственной прошивке
  pulsar работает полноценным координатором для Zigbee2MQTT и ZHA (как USB-стик ConBee) или
  роутером (ретранслятором) в существующей сети (см. [Zigbee](#zigbee-миди)); в профиле Ricardo
  runtime Zigbee выключен.

Ни одна проприетарная библиотека Яндекса в репозитории не распространяется: демон загружает их с
самой колонки во время работы.

> Проект не связан с Яндексом. Всё, что вы делаете с устройством, — на ваш страх и риск.

## Что появляется в Home Assistant

Если не указано иное, сущность есть на всех моделях. Часы (все сущности и действия `clock_show_*`)
есть у Миди и Лайт 2, а у Мини 2 и Мини 3 — если панель найдена при старте; у Мини часов нет.
Датчик освещённости — у Миди, Лайт 2 и Мини 3, у Мини 2 — если найден при старте.
«Clock auto brightness» — при наличии часов и успешно открытого датчика. Аппаратный переключатель
микрофона — у Миди, Лайт 2, Мини 2 и Мини 3. Что есть и чего нет у Мини — в разделе [Мини](#мини).

| Сущность | Что делает |
|---|---|
| Assist satellite | Голосовой ассистент: активационные фразы «Алиса» / «Яндекс», таймеры, объявления (`assist_satellite.announce`), продолжение диалога |
| Media player | Воспроизведение медиа и TTS, громкость, mute (полная тишина: музыка, ответы, объявления и звуки колонки); при обрыве сети поток переподключается (3 попытки) с того же места; виден в Music Assistant через провайдер «Home Assistant» |
| Switch «Микрофоны» | Микрофоны: включён — колонка слушает, выключен — нет (мут из HA или кнопкой на корпусе). Раньше сущность называлась «Mute microphones» с обратной полярностью. «Выключить» ставит мут из HA, «включить» снимает его, если мут кнопкой не активен. Пока кнопка держит мьют, «включить» из HA не действует: колонка сразу возвращает «выключено». Если микрофоны выключены только из HA, кнопку мута нужно нажать два раза: первое нажатие включает мут кнопкой, второе выключает его и заодно снимает мут из HA (у Мини — см. [Мини](#мини)) |
| Switch «Часы на дисплее» | Часы на передней панели |
| Switch «Clock colon blink» | Мигание двоеточия при показе времени; по умолчанию включено. Выключено — двоеточие горит постоянно |
| Switch «Clock auto brightness» | Автояркость часов по датчику освещённости: освещённость пересчитывается в уровень по перцептивной кривой (как приглушение кольца), поэтому в сумерках часы темнее, чем по линейной кривой, а в темноте гаснут почти полностью; на свету горят в полную силу. Выключено — часы светятся на уровне «Clock brightness» при любом свете |
| Number «Clock brightness» | Яркость часов (при включённой автояркости — верхний предел, по датчику в темноте она падает; при выключенной — уровень как есть) |
| Text «Clock text» | Свой текст на часах (до 64 символов): латиница, цифры, приближённая кириллица; `:` зажигает двоеточие. До 4 знаков — по центру, длиннее — бегущая строка по кругу, пока текст не очищен |
| Select «Clock face» | Рожицы на часах (Smiley, Sad, OwO, >w< и др.) и анимации Blink / All faces; текст и рожица заменяют друг друга |
| Number «Clock text speed» | Скорость бегущей строки, мс на шаг (100–2000) |
| Select «Clock music» | Музыка на часах во время воспроизведения: Off (по умолчанию) / Levels — у каждой цифры свой уровень (нижний, средний, верхний сегмент) по двум соседним полосам спектра, в пределах того, как эти полосы менялись за последние секунды (так видны изменения, а не общий тембр песни); время периодически показывается. Заданные «Clock text» или «Clock face» скрывают «Clock music». Источник тот же, что у «Music visualization» |
| Actions `clock_show_text` / `clock_show_face` | `esphome.<устройство>_clock_show_text` (`text`, `seconds`) и `…_clock_show_face` (`face`, `seconds`): временно показать текст или рожицу поверх «Clock text» / «Clock face»; `seconds` ≤ 0 — один проход строки или 5 с, максимум 3600; пустое значение убирает показ |
| Light «Подсветка» | Кольцо как обычная лампа: цвет, яркость, плавные переходы (transition, до 60 с), эффекты Rainbow, Breathe, Color loop, Comet, Twinkle, Fire, Aurora, Lava lamp, Candle, Night light — одинаковые на всех моделях (на Миди лента из 24 светодиодов, на Лайт 2 — 3, у Мини 2, Мини 3 и Мини — 6); если есть датчик освещённости, в темноте кольцо и логотип приглушаются |
| Select «Music visualization» | Светомузыка во время воспроизведения: Off / All styles (по умолчанию: Spectrum → Pulse → Disco → Polar по кругу) / Spectrum / Pulse / Disco / Polar. Источник — визуализатор Sendspin (Music Assistant), если сервер его присылает, иначе спектр звука, который играет сама колонка. Включённая лампа «Подсветка» важнее светомузыки |
| Number «LED speed» | Скорость эффектов и светомузыки, 0,25–4× |
| Number «Громкость объявлений» | Абсолютная громкость объявлений `assist_satellite.announce` и ответов ассистента (TTS) на той же кривой, что и общая громкость: 0–100 % с шагом 5, по умолчанию 100 %. 5 % здесь звучат как обычные 5 % колонки; громче текущей общей громкости объявление не играет (предел — аппаратный мастер), поэтому 100 % по-прежнему означают «как основная громкость». Общая громкость, музыка, звуковые сигналы и звонок таймера не меняются. Сохраняется между перезапусками |
| Switch «Wake sound» | Звук начала прослушивания после активационной фразы и по кнопке действия; по умолчанию включён. Если выключить и его, и «Voice indication», колонка начинает слушать без звука и без индикации |
| Number «Microphone gain» | Усиление звука запроса перед отправкой в HA, 0–40 дБ с шагом 1, по умолчанию 34 — прежний уровень (на Миди и Лайт 2 выход 9 = выход 6 × 50), поэтому обновление не меняет поток в STT. В HA идёт главный канал распознавания стока (`VQE_OMNI`); на Мини 1, где усиленный канал перегружен, поставьте 0. Меняется сразу, пре-ролл при смене очищается; сохраняется между перезапусками |
| Number «Follow-up duration» | Сколько ждать начала следующей реплики, если после ответа HA продолжает разговор: 0–10 с, по умолчанию 10; 0 — не слушать продолжение |
| Switch «Voice indication» | Показывать на кольце и часах «слушает / думает / отвечает» (ошибка и звонок таймера видны всегда) |
| Select «Case color» | Коррекция цвета под ткань корпуса (матрицы штатной прошивки из `/system/vendor/quasar/ledconfigs`); None — без коррекции; если матриц нет (у Мини их нет, на некоторых прошивках Мини 2 каталог пуст), сущность не публикуется — на любой модели |
| Action `led_show` | `esphome.<устройство>_led_show` (`effect`, `color`, `seconds`): временно показать эффект (или сплошной цвет при пустом `effect`) цветом `#RRGGBB` (пусто — белый) на полной яркости поверх лампы и светомузыки; временные сигналы колонки (громкость, ассистент, таймер, краткий сигнал переключения микрофонов) идут поверх показа; `seconds` ≤ 0 — 5 с, максимум 3600; пустые `effect` и `color` снимают показ |
| Binary sensor «Hardware mic mute» | Аппаратный переключатель микрофонов на корпусе (нет у Мини): `on` — микрофоны отключены кнопкой. Защёлка режет звук микрофонов в железе, программно включить их нельзя. Поэтому после нажатия кнопки микрофоны включаются только кнопкой — это аппаратная гарантия приватности; HA и приложение показывают причину |
| Sensor «Illuminance» | Датчик освещённости, лк |
| Event «Button» | Для автоматизаций: `volume_up`, `volume_down`, `action`, `action_long` (нет у Мини) |
| Button «Restart» | Перезапуск демона на колонке |
| Update «Firmware» | Новая версия pulsar из GHCR: «Установить» в HA (см. [Обновление из Home Assistant](#обновление-из-home-assistant)) |
| Switch «Auto update» | Ставить новые версии автоматически (по умолчанию выключен) |
| Switch «Nearest station answers» | Отвечает ближайшая колонка (по умолчанию выключен; в профиле Ricardo включается отдельно, см. [Несколько колонок](#несколько-колонок)) |
| Switch «Command right after wake word» | Команда, сказанная сразу после активационной фразы, без паузы («Алиса который час»), не теряет начало: звук сразу после фразы идёт в запрос, его длина подобрана так, чтобы сама фраза в распознавание не попадала. По умолчанию включён; выключите, если в тексте запроса появляется кусок «Алиса» / «Яндекс» (звук после срабатывания всё равно не теряется). У Мини нет: длина для неё не измерена |
| Диагностика | «Wi-Fi signal» (дБм), «Uptime», «IP address», «Version» |

Часовой пояс для часов берётся из Home Assistant. Журнал демона виден в HA (журналы устройства
ESPHome). К колонке могут одновременно подключаться несколько клиентов (до 4), например HA и
ESPHome Dashboard; голосовой конвейер обслуживает последний подписавшийся на него клиент, а когда
тот отключается или отписывается — снова предыдущий (обычно HA).

«Follow-up duration» сохраняется между перезапусками. Отсчёт идёт с момента, когда HA начал
слушать продолжение; если вы заговорили, ожидание снимается и реплика не обрывается. Если ответа
нет, разговор заканчивается тихо, без ошибки на кольце. Ограничение по времени работает, когда
начало речи определяет сам HA; с распознавателем, который сам определяет конец фразы (например,
HA Cloud STT v2 из Labs), настройка только включает или выключает продолжение. 0 закрывает и уже
открытое ожидание.

Таймеры: на часах обратный отсчёт ближайшего из запущенных таймеров (если все на паузе —
таймера с наименьшим остатком); он показывается вместо `clock_show_*`, «Clock text» и «Clock face»,
а короткие анимации (пауза, смена трека) ненадолго перекрывают отсчёт.
Если HA не продвигает диалог (30 с прослушивания или 120 с обработки без событий), колонка сама
завершает его и показывает ошибку на кольце.

Текст и рожица на часах не сохраняются между перезапусками (после перезапуска — время), скорость и
«Clock music» сохраняются. Выключатель «Часы на дисплее» гасит всё, кроме кода сопряжения Sendspin.

### Кнопки и индикация

- **Кнопка действия:** короткое нажатие — начать диалог без активационной фразы; пока станция
  слушает или ждёт ответа — отменить диалог; во время ответа — прервать его; при звонке таймера —
  выключить. Долгое нажатие только отправляет событие в HA.
- **Громкость +/−:** шаг 5 % (с промежуточной громкости — до ближайшей ступени), уровень
  показывается на кольце и на часах (если они есть), звучит штатный щелчок; тот же щелчок у
  «громче» / «тише». Щелчка нет, когда уровень не изменился (0 % или 100 %), пока станция слушает
  или отвечает, во время объявления и звонка таймера, а также при изменении громкости из HA или
  Music Assistant. На Миди, Лайт 2, Мини 2 и Мини 3 шкала громкости та же, что у штатной
  прошивки: 5 % — одна её ступень, 10 % в HA соответствует «1» у Алисы (у Мини — см. [Мини](#мини)).
- **Кольцо:** анимации в стиле штатной Алисы (те же цвета и ритм, нарисованы заново): слушает,
  думает, отвечает, ошибка, звонок таймера, запуск таймера (зелёные точки гаснут за 15 с),
  громкость. Отключение микрофонов: на Миди — красная волна по ленте и красный логотип, на
  Лайт 2, Мини 2 и Мини 3 — вспышка и ровный тусклый красный, на Мини — красное кольцо; у всех
  моделей, кроме Миди, этот красный перекрывает лампу «Подсветка» и светомузыку, но уступает временным
  сигналам колонки (громкость, ассистент, таймер, `led_show`).
  Красная вспышка после «Алиса» значит, что голосовой ассистент HA не подписан на колонку (HA не
  подключён или ассистент не выбран).
- **Часы (Миди, Лайт 2):** анимации штатной прошивки Лайт 2 (нарисованы заново, одинаковые на
  Миди и Лайт 2): «глаза» при запуске демона, слушает / думает / отвечает (с «Voice indication»),
  звонок таймера, «||» при паузе (голосом или из HA) и бегущие столбики при «дальше» / «назад».
  Средняя точка между точками двоеточия есть только на Лайт 2.

### Локальные голосовые команды

Модель команд слушает, пока что-то звучит: музыка, ответ ассистента, объявление или звонок
таймера; в тишине без «Алиса» команды не распознаются. Пока идёт диалог с HA, командный спотер
выключен, поэтому все слова, включая «стоп» и «хватит», уходят в Home Assistant: «Рикардо, стоп»
выключает звонок будильника и возвращает музыку через HA (см. [RICARDO.md](RICARDO.md)), а не
ставит её на паузу локально. Окна «первые 2,5 с после Алисы», которое открывает любые команды в
upstream, в форке нет: upstream не выключает спотер на время диалога, а форк выключает. Если HA уже
распознал запрос и начал его выполнять, сделанное не откатывается. Без «Алиса» колонки не
договариваются, кто выполняет команду, поэтому каждая выполняет только своё: «стоп» и «хватит» —
везде; «громче» и «тише» — если колонка звучит (музыка, ответ, объявление, таймер) или её музыка на
паузе; «пауза», «продолжи», «дальше», «назад» — только для своей музыки. Музыка на паузе (или
остановленная в Music Assistant) остаётся своей 2 часа.

Во время диалога pulsar также проверяет готовый текст распознавания HA, так что «стоп» действует,
даже если модель команд его пропустила. Проверка принимает только стоп-слова без других слов
запроса, в том числе повтор («стоп, стоп»). В диалоге от кнопки, продолжения разговора или из HA
она выключает звонок таймера и отменяет диалог; в диалоге от «Алиса» локального действия нет —
запрос уходит в HA и работает как «Алиса, стоп» из таблицы ниже.

| Фраза | Действие |
|---|---|
| стоп / хватит | выключить звонок таймера, иначе отменить диалог или прервать ответ, иначе пауза музыки («Алиса, стоп» отменяет запрос и ставит музыку на паузу) |
| пауза | пауза |
| продолжи / играй | продолжить воспроизведение |
| громче / тише | громкость на деление шкалы Алисы (10 %) вверх / вниз; с промежуточной громкости — до ближайшего деления |
| дальше / следующий, назад | следующий / предыдущий трек (Sendspin) |

### Несколько колонок

Колонки с pulsar в одной сети договариваются, кто ответит: услышав активационную фразу, каждая
сообщает соседям по сети, насколько громко её услышала, и коротко ждёт ответов. Отвечает колонка,
которая услышала фразу громче, то есть обычно ближайшая; колонка, которая в этот момент отвечает,
читает объявление или звонит таймером, своё слово не уступает. На остальных кольцо мигает и
гаснет, звука нет, «Алиса, громче» меняет громкость только у ответившей. Звук сигнала активации
из-за ожидания запаздывает на доли секунды; сказанное сразу после «Алиса» не теряется.

С выключенным «Nearest station answers» (или если пакеты не доходят: точка доступа режет
широковещательный трафик, колонки в разных подсетях) отвечает та, чей запрос первым дошёл до HA:
остальные HA отклоняет как повтор, и они молча гаснут. Другие голосовые спутники (Voice PE и т. п.)
в договорённости не участвуют.

## Установка

> В монорепозитории установщик больше не публикуется готовым архивом: он собран на Rust и
> собирается из исходников (см. [Сборка из исходников](#сборка-из-исходников)). Архивы ниже —
> из upstream-релизов.

Скачайте архив для своего компьютера из
[последнего релиза](https://github.com/Morvex885/pulsar/releases/latest), распакуйте и запустите
`pulsar-install`.

| Компьютер | Архив |
|---|---|
| Windows | `pulsar-windows-amd64.zip` |
| macOS (Apple Silicon) | `pulsar-macos-arm64.tar.gz` |
| macOS (Intel) | `pulsar-macos-amd64.tar.gz` |
| Linux x86-64 | `pulsar-linux-amd64.tar.gz` |
| Linux ARM64 (например, Raspberry Pi) | `pulsar-linux-arm64.tar.gz` |

Linux и macOS (подставьте имя своего архива):

```sh
curl -fLO https://github.com/Morvex885/pulsar/releases/latest/download/pulsar-linux-amd64.tar.gz
tar -xzf pulsar-linux-amd64.tar.gz && cd pulsar
./pulsar-install                 # найти колонки в сети и выбрать, куда ставить
./pulsar-install 192.0.2.10    # или сразу по адресу
./pulsar-install --list          # только показать найденное
```

Windows (PowerShell или командная строка):

```bat
curl.exe -fLO https://github.com/Morvex885/pulsar/releases/latest/download/pulsar-windows-amd64.zip
tar -xf pulsar-windows-amd64.zip
cd pulsar
.\pulsar-install.exe
```

Можно и распаковать архив в Проводнике и запустить `pulsar-install.exe` двойным щелчком (см.
[Windows и macOS](#windows-и-macos)).

В архиве уже собраны программы для всех поддерживаемых моделей колонок и dropbear, рядом лежат
служебные скрипты.

Установщику нужен `adb`. Если его нет в `PATH`, при первом запуске установщик скачивает Android
SDK Platform-Tools с dl.google.com (условия Google) в каталог `platform-tools` рядом с собой. Для
Linux ARM64 Google их не собирает — поставьте `adb` сами (`sudo apt install adb`).

Без адреса установщик находит Станции через mDNS (и штатные, и уже переведённые на pulsar). Затем
он подключается к ним по adb, определяет модель и показывает список. Поддерживаемые колонки с
root-доступом пронумерованы. Остальные (другие модели, adb без root) перечислены с причиной
пропуска.

Если колонка не находится, `--scan` ищет открытый adb (порт 5555) по всей подсети /24. Тогда
другие Android-устройства в сети могут показать запрос «Разрешить отладку?» — его можно отклонить.

Установщик из копии репозитория сначала собирает программу: нужны инструменты сборки (см.
[docs/development.md, «Сборка»](https://github.com/Morvex885/pulsar/blob/main/docs/development.md#сборка)).
Затем на каждую выбранную колонку он:

1. копирует демон и служебные скрипты в `/data/pulsar`; если бинарник изменился,
   прежний сохраняется как `.prev` (тот же бинарник не копируется и `.prev` не трогает);
2. записывает скрипт автозапуска `/etc/init.d/S99zpulsar`. При загрузке система выполняет его
   после скрипта Яндекса; он запускает `/data/pulsar/boot.sh` и dropbear, если тот установлен. Для
   записи корневая ФС на несколько секунд перемонтируется на запись и сразу возвращается в режим
   только для чтения; если файл уже актуален, ничего не перемонтируется. Если корневая ФС защищена
   (dm-verity, device-mapper) или `/etc` лежит не на ней, скрипт не записывается: установщик
   сообщает причину и в конце пишет, что после перезагрузки pulsar сам не запустится;
3. если прежняя версия добавляла строки автозапуска в `/data/quasar/rootkeeper.sh`, удаляет ровно
   эти строки (резервная копия `rootkeeper.sh.bak-<время>`); остальное содержимое файла не
   меняется;
4. останавливает стек Яндекса и запускает демон; через ~10 с и ещё раз через ~30 с проверяет по
   журналу, что он поднялся и не падал, и при неудаче предлагает вернуть прежний бинарник.

Вне `/data` установщик пишет только `/etc/init.d/S99zpulsar`, больше системный раздел не трогается.
Повторный запуск обновляет установленную версию. `--yes` ставит на все найденные колонки без
вопросов, `--no-enable` не останавливает стек Яндекса и не запускает демон (шаг 4).

Дальше в Home Assistant: **Настройки → Устройства и службы**. Колонка обнаружится сама как
ESPHome-устройство `yandex-midi-xxxxxx`, `yandex-lite2-xxxxxx`, `yandex-mini2-xxxxxx`,
`yandex-mini3-xxxxxx` или `yandex-mini-xxxxxx`. Если не обнаружилась, добавьте интеграцию ESPHome
вручную с IP колонки и портом `6053`; ключ шифрования HA создаст сам (см.
[Шифрование API](#шифрование-api)). В настройках устройства выберите конвейер Assist и
активационную фразу.

### SSH (необязательно)

```sh
./pulsar-install --ssh            # дополнительно поставит dropbear
```

Устанавливает dropbear в `/data/dropbear` на порт 22. **Вход под root с пустым паролем** (`-B`).
Ставьте только в доверенной сети или поменяйте флаги в `ssh/start.sh`.

### Windows и macOS

> Установщик для Windows и macOS пока не проверен на реальных компьютерах. Если что-то не
> работает, напишите в issues.

- **Windows.** `pulsar-install.exe` — консольная программа: если запустить её двойным щелчком, окно
  в конце ждёт Enter, чтобы можно было прочитать вывод. Архив, скачанный браузером и распакованный
  в Проводнике, может вызвать SmartScreen: «Система Windows защитила ваш компьютер» → «Подробнее» →
  «Выполнить в любом случае»; у архива, скачанного через `curl.exe` и распакованного `tar`, как в
  разделе [Установка](#установка), такой пометки нет. Если `adb` уже есть в `PATH` (например, из
  Android Studio), используется он. Подключение колонки по USB не описано: используйте adb по сети.
- **macOS.** Скачивайте архив через `curl`, как в разделе [Установка](#установка). Для архива, уже
  скачанного браузером: `xattr -dr com.apple.quarantine pulsar`. Если поиск ничего не находит или
  adb пишет «No route to host», разрешите терминалу доступ к локальной сети: «Системные настройки»
  → «Конфиденциальность и безопасность» → «Локальная сеть». Сборка демона на macOS не
  поддерживается — используйте архив.

## Обновление и откат

### Обновление из Home Assistant

Колонка сама проверяет публичный OCI-артефакт
`ghcr.io/proflyder/pulsar-firmware` (тег `latest`, аннотация
`org.opencontainers.image.version`) через минуту после запуска и затем каждые
6 часов; проверить сразу — «Проверить наличие обновлений» в HA
(`homeassistant.update_entity`). Когда выходит новая версия, сущность
«Firmware» в HA показывает её; кнопка «Установить» ставит её. Колонка
скачивает `pulsar-<arch>.bin` по HTTPS (сертификат проверяется), сверяет
digest слоя и `SHA256SUMS` и проверяет, что программа запускается на этой
колонке и сообщает нужную версию. Только после этого она заменяет бинарник
(прежний остаётся как `.prev`) и перезапускается — разговор или музыка в этот
момент прервутся. Пока идёт установка, часы погашены; если установка не
удалась, они снова показывают время.

С включённым переключателем «Auto update» колонка ставит новую версию сама, дождавшись тишины (нет
диалога, музыки, объявления или звонка таймера). Если новая версия не запустится, через
автоматический откат (см. ниже) вернётся прежняя, и эту версию автообновление больше не будет
ставить; вручную её поставить можно.

Прошивка старше `v0.5.1007` читает прежние GitHub Releases и через HA не
обновится: на такую станцию бинарник ставится вручную. Обновляется демон;
`boot.sh`, `supervise.sh` и `ctl.sh` обновляет установщик. В профиле Ricardo
Zigbee-модуль выключен (`FEATURES.zigbee = false`), поэтому образы
`zigbee-*.ybl` в обновлении не участвуют.

### Автоматический и ручной откат

Если демон 5 раз подряд падает, не проработав 5 минут, вместо него ставится `.prev` (сломанный
бинарник сохраняется как `.bad`); если падает и он — колонка возвращается стеку Яндекса, как после
`ctl.sh disable`. Перезапуск кнопкой «Restart» в HA или через `ctl.sh restart` падением не
считается, если демон до этого проработал хотя бы 5 с.

Откат на предыдущую версию вручную:

```sh
cd /data/pulsar && mv pulsar.prev pulsar && ./ctl.sh restart
```

### Удаление

Вернуть стек Яндекса, удалить `/data/pulsar` и скрипт автозапуска (корневую ФС нужно ненадолго
перемонтировать на запись):

```sh
/data/pulsar/ctl.sh disable
rm -rf /data/pulsar
mount -o remount,rw / && rm -f /etc/init.d/S99zpulsar; mount -o remount,ro /
```

## Music Assistant

Music Assistant с поддержкой Sendspin находит колонку сам: плеер «Яндекс Станция Миди»,
«Яндекс Станция Лайт 2», «Яндекс Станция Мини 2», «Яндекс Станция Мини 3» или «Яндекс Станция
Мини» с типом **Sendspin**. Музыка идёт без потерь (FLAC), громкость и голосовые команды колонки
управляют плеером MA. Синхронное воспроизведение в группах с другими Sendspin-плеерами заложено
протоколом, но пока не проверялось. Задержку вывода задают в настройках Sendspin-плеера в Music
Assistant; MA хранит её сам и присылает при каждом подключении. Для Миди прошивка Яндекса
использует поправку около 22 мс (не измерено) — можно начать с неё.

По умолчанию колонка принимает Sendspin-подключения без сопряжения. Чтобы требовать сопряжение:

```sh
adb shell 'echo 0 > /data/pulsar/sendspin/unpaired_access'
adb shell /data/pulsar/ctl.sh restart
```

После этого при запросе сопряжения на часах появляется «----»: нажмите кнопку действия, и колонка
покажет код сопряжения. У Мини часов и кнопки действия нет: код сопряжения пишется в журнал
(`/data/pulsar/ctl.sh log`). Постоянный pairing-токен `SP:…` в журнал не пишется: он позволяет
подключиться к колонке.

## Звонок на колонку

Станция — endpoint `STATION` сервиса intercom: с телефона можно позвонить на колонку, как
по интеркому. Звонок приходит через сигналинг `home.v1.IntercomService` (исходящее
соединение колонки), звук идёт напрямую WebRTC (Opus 48 кГц, DTLS-SRTP) — сервер только
сводит участников и не несёт медиа.

- Входящий звонок колонка принимает **сама** после короткого сигнала: звонок на колонку —
  это интерком, а не вызов, который надо подтверждать.
- Во время звонка кольцо и часы показывают отдельное «звонковое» кольцо (циан,
  обегающие точки), спотеры («Алиса»/«Рикардо» и локальные команды) выключены, музыка и
  Sendspin на паузе.
- Микрофон: очищенный от эха поток VQE уходит собеседнику. Мут колонки (кнопка или HA)
  глушит только uplink — собеседника по-прежнему слышно; мут виден на кольце.
- Кнопка действия на корпусе сбрасывает звонок. Телефон, положивший трубку, тоже
  завершает разговор.
- После звонка всё возвращается: спотеры, музыка, обычное кольцо.
- Аудио звонка нигде не записывается; в логах только события состояний, без SDP и
  медиаданных.

Звонок включается провижинингом, без правки `state.conf` (рядом с ним, каталог
`/data/pulsar`):

| Файл | Что |
|---|---|
| `intercom_url` | база сервиса, например `https://intercom.home.<home-suffix>/v1`; нет файла — звонок выключен |
| `intercom_token` | device token станции, права `0600` (выдаётся при регистрации endpoint) |
| `intercom_ca.pem` | необязательный приватный CA, если сертификат сервиса не от публичного |

Звонок работает только из LAN или через VPN: прямого входящего порта на колонке нет,
соединение всегда исходящее. Задержка downlink ограничена dmix станции (см.
[docs/call-latency-probe.md](docs/call-latency-probe.md), «Результаты»).

## Zigbee (Миди)

> В профиле Ricardo runtime Zigbee выключен (`FEATURES.zigbee = false` в
> `satellite/crates/pulsar/src/controller/wiring.rs`): раздел описывает
> upstream-возможность, которой в текущей сборке нет.
>
> Экспериментально. Проверено на одной Миди: координатор в Zigbee2MQTT (zigbee-herdsman) и ZHA
> (zigpy) — создание сети с параметрами из их конфига, перезапуски без пересоздания, сканирование
> эфира, подключение кнопки Aqara (интервью, нажатия, обновление прошивки модуля без потери
> сети); роутер в сети Zigbee2MQTT. Перенос живой сети со стика и большие сети ещё не проверялись.

В Миди есть Zigbee-модуль, на котором работает весь стек Zigbee; сеть (PAN ID, ключи,
подключённые устройства) хранится в его собственной флеш-памяти. pulsar ставит в модуль свою
прошивку (собирается из `radio/` на открытом Telink Zigbee SDK и устанавливается рядом с
демоном). Роль выбирается в HA (сущность «Zigbee role»):

- **Off** (по умолчанию) — pulsar модуль не трогает.
- **Coordinator** — сетевой координатор для Zigbee2MQTT и ZHA, как USB-стик ConBee: колонку
  указывают в их настройках, дальше всё управление (сопряжение, устройства, группы, бэкапы) — из их
  интерфейса. Параметры сети (PAN ID, расширенный PAN ID, ключ, канал, IEEE-адрес координатора)
  задаёт Zigbee2MQTT или ZHA.
- **Router** — колонка становится роутером (ретранслятором) в чужой сети, как любое Zigbee-устройство
  с питанием от сети: например, в сети Zigbee2MQTT с USB-стиком. Порт 6638 в этой роли закрыт.

При выборе роли pulsar перезапускается и, если в модуле не та прошивка, записывает нужную через
загрузчик модуля (20–30 секунд; ход виден в сенсоре «Zigbee»; перезапуск и обновление из HA в это
время не выполняются). Каждая прошивка хранит свою сеть в своей области флеш-памяти, поэтому сети
обеих ролей переживают переключение туда и обратно; сеть, которую создал Яндекс, тоже остаётся в
модуле, и прошивка Яндекса вернётся сама, если включить родной стек (`ctl.sh disable`). Если
обновление pulsar принесло новую сборку прошивки текущей роли, она записывается в модуль сама при
первом запуске (сеть сохраняется). Если запись прервалась (например, отключилось питание), pulsar
при следующем запуске запишет прошивку заново. Прошивка, которую модуль не принял, повторно не
записывается до смены роли или следующего обновления.

### Координатор

pulsar отдаёт модуль по протоколу deCONZ (ConBee/RaspBee) на TCP-порту **6638**:

- **Zigbee2MQTT**:
  ```yaml
  serial:
    port: tcp://<IP колонки>:6638
    adapter: deconz
  ```
  При первом запуске Zigbee2MQTT создаёт в модуле сеть со своими `pan_id`, `ext_pan_id`,
  `network_key` и каналом; дальше перезапуски сеть не трогают. Чтобы перенести сеть с другого
  адаптера (например, USB-стика), оставьте в конфиге те же `pan_id`, `ext_pan_id`, `network_key`
  и канал и файл `coordinator_backup.json`: Zigbee2MQTT запишет в модуль IEEE-адрес и счётчик
  кадров из резервной копии, и устройства должны остаться в сети (на живой сети не проверено).
  Индивидуальные ключи устройств Zigbee 3.0, выданные старым адаптером, не переносятся: такое
  устройство работает дальше, но если оно потеряет сеть (смена канала, долгое отключение), его
  придётся подключить заново. Старый адаптер после переноса отключите — два координатора с одной
  сетью мешают друг другу.
- **ZHA** находит его сам (mDNS `_zigbee-coordinator._tcp`): «Настройки → Устройства и службы»
  покажет найденный Zigbee-координатор «Яндекс Станция Миди». Вручную: ZHA → тип радио
  **deCONZ**, путь `socket://<IP колонки>:6638`.

Одновременно работает один клиент: новое подключение вытесняет старое. Порт 6638 открыт без
авторизации (как у сетевых координаторов вообще): любой в локальной сети может подключиться,
вытеснить HA, открыть сеть для подключения, управлять устройствами или стереть сеть.

Ограничения: ключи устройств только по общему ключу ZigBeeAlliance09 (install code не
поддерживается), таблицы соседей и маршрутов самого координатора не отдаются (карта сети строится
по роутерам), Green Power (кнопки без батареек) не поддерживается.

### Роутер

Подключение к сети в роли Router:

1. В Zigbee2MQTT (или ZHA) разрешите подключение устройств («Permit join»).
2. В HA нажмите кнопку «Zigbee join network» у колонки. Модуль ищет открытую сеть на всех
   каналах; через несколько секунд колонка появится в Zigbee2MQTT как роутер, а сенсор «Zigbee»
   покажет «router: in network …».
3. Кнопка «Zigbee leave network» выводит колонку из сети (координатор получает Leave).

В роли роутера колонка подключается к первой найденной открытой сети: держите подключение
открытым только в своей сети.

## Сборка из исходников

Демон и установщик написаны на Rust и собираются на Linux или WSL2 через Bazel
([Bazelisk](https://github.com/bazelbuild/bazelisk), Bazel 9.3.2); для запуска установщика из
копии репозитория нужен ещё `cargo` из [rustup](https://rustup.rs/) (версия — `rust-toolchain.toml`):

- Bazelisk (`bazel` в PATH) — версия Bazel из `.bazelversion`;
- `git` и компилятор C/C++ для хоста (`cc`/`c++`); Rust 1.99.1, zig 0.14.1 и sendspin-cpp
  скачивает и собирает сам Bazel по пинам `MODULE.bazel` — rustup, cargo-zigbuild, cmake и ninja
  не нужны;
- `adb` из Android platform-tools.

```sh
bazel test //projects/station/pulsar/satellite/...    # rustfmt, clippy, тесты на компьютере
bazel build -c opt --platforms=//platform/bazel/zig:armhf_linux \
  --define=pulsar_version="$(node platform/ci/version.mjs --unit pulsar)" \
  //projects/station/pulsar/satellite:station_binary  # одна архитектура
cd projects/station/pulsar
cargo run -p pulsar-installer -- 192.0.2.10  # установщик; сам собирает Bazel
```

`aarch64_linux` — обычный userspace Миди (glibc 2.36), `armhf_linux` — 32-битный
userspace Мини, Лайт 2, Мини 2, Мини 3 и образов Миди с armhf (glibc 2.23). Сборка
`station_binary` даёт `bazel-bin/projects/station/pulsar/satellite/pulsar` (стрипнутый) и
`pulsar.debug` (нестрипнутый, с символами; `pulsar` несёт `.gnu_debuglink` для `addr2line`). CI и установщик копируют их в
`satellite/build/<arch>/`. `--version` печатает версию из `VERSION`, переданную в
`--define=pulsar_version`.

Для профиля Ricardo положите модель в `satellite/wakewords/ru_ricardo_mww.tflite`
(инструкция и SHA-256 — `satellite/wakewords/README.md`). Установщик скопирует её
в `/data/pulsar/wakewords/` с проверкой хеша.

`alsa-lib` не линкуется: демон загружает её с колонки при запуске. Установщик смотрит, какой из
загрузчиков `/lib/ld-linux-aarch64.so.1` и `/lib/ld-linux-armhf.so.3` есть на станции, и ставит
эту сборку. Для Миди обычен aarch64; если его нет, а armhf есть, ставится armhf (образы с
32-битным userspace). Лайт 2, Мини 2, Мини 3 и Мини — только armhf. С `--ssh` установщик
дополнительно собирает dropbear (`ssh/build.sh`).

Прошивки координатора и роутера для Zigbee-модуля Миди собирает `radio/build.sh` (нужны `unzip` и 32-битная
библиотека C: `sudo dpkg --add-architecture i386 && sudo apt-get install libc6:i386`, потому что
тулчейн Telink — 32-битные программы x86). Он скачивает закреплённую версию Telink Zigbee SDK и
тулчейн (проверяется sha256) и кладёт результат в `radio/out/zigbee-coordinator.ybl` и
`radio/out/zigbee-router.ybl`; установщик копирует их на Миди, если они собраны. В архивах релиза
они уже есть.

Pulsar живёт в монорепозитории: PR в `develop` собирает обе архитектуры и прошивки Zigbee-модуля
через GitHub Actions и публикует `ghcr.io/proflyder/pulsar-firmware:tree-<hash>` с provenance.
Merge в `develop` с новым `VERSION` только продвигает этот digest на теги `<VERSION>` и `:latest`
(`pulsar-<arch>.bin`, `zigbee-*.ybl`, `SHA256SUMS`), после approve в Environment `Station`
`deploy-station` раскатывает его через Home Assistant; повторной сборки нет. GitHub Releases и
теги не используются; `.debug`-файлы остаются артефактами workflow для разбора crash-отчётов.

## Управление

На колонке (`adb shell` или ssh):

```sh
/data/pulsar/ctl.sh status    # кто сейчас работает: демон или стек Яндекса
/data/pulsar/ctl.sh log 100   # журнал (/tmp/pulsar.log)
/data/pulsar/ctl.sh restart
/data/pulsar/ctl.sh reload    # перезапустить и надзорный скрипт (после обновления supervise.sh)
/data/pulsar/ctl.sh api-key   # задан ли ключ шифрования API (сам ключ не выводится); см. ниже
/data/pulsar/ctl.sh disable   # вернуть стек Яндекса, в том числе после перезагрузки
/data/pulsar/ctl.sh enable
/data/pulsar/pulsar --version
```

Журнал лежит в `/tmp` (обнуляется при перезагрузке) и ротируется при 1 МБ.

Настройки (громкость, свет, часы, активационная фраза, часовой пояс, автообновление) хранятся в
`/data/pulsar/state.conf`; после отката на `.prev` колонка читает тот же файл и играет так же
громко.

### Шифрование API

Колонка поддерживает шифрование ESPHome API (Noise), как обычные ESPHome-устройства. Пока ключа
нет, API работает без шифрования, и свежий Home Assistant при подключении сам создаёт ключ и
записывает его на колонку (`/data/pulsar/api_key`); дальше соединение шифруется.
Задать ключ вручную (base64 от 32 байт, как в ESPHome) или убрать его:

```sh
/data/pulsar/ctl.sh api-key <base64>   # задать ключ, демон перезапустится; затем ввести его в HA
/data/pulsar/ctl.sh api-key clear      # удалить ключ, демон перезапустится
```

После смены или удаления ключа вручную HA попросит переавторизовать устройство. **Внимание:**
версии демона без поддержки шифрования (и откат на такую через `.prev`) не смогут общаться с HA,
который уже хранит ключ: удалите ключ в настройках устройства в HA или удалите и заново добавьте
устройство.

## Модели: особенности

### Мини 2

Установщик ставит armhf-сборку: ядро на колонке 64-битное, пользовательский режим 32-битный.

- Голосовой сценарий с HA, воспроизведение (включая Sendspin), кольцо из 6 светодиодов, кнопки и
  отключение микрофонов проверены на ранней версии демона ([#9](https://github.com/Morvex885/pulsar/pull/9)).
  Логотипа и Zigbee нет.
- Качество распознавания не измерялось: своих моделей спотера у Мини 2 нет, используются
  модели Лайт 2.
- Часы и датчик освещённости есть не на всех колонках: на колонке из #9 (прошивка 0.369) их нет —
  вероятно, это вариант без часов: по [вики](https://hackalice.me/devices/station-mini2/) Мини 2
  продаётся с часами и без; на колонке из [#38](https://github.com/Morvex885/pulsar/issues/38)
  (0.372) есть. Подстройка яркости по датчику на Мини 2 пока не проверялась.

### Мини 3

Экспериментальный профиль: что проверено, а что нет — в
[docs/mini3.md](https://github.com/Morvex885/pulsar/blob/main/docs/mini3.md). Датчик освещённости
есть; часы — если панель найдена при старте.

### Мини

Данные контрибьютора ([#35](https://github.com/Morvex885/pulsar/pull/35)). Установщик ставит
armhf-сборку.

- Нет часов, датчика освещённости, аппаратного переключателя MUTE, кнопки TALK, кнопок громкости,
  логотипа и Zigbee; значит, нет и сущностей часов, «Illuminance» и события «Button». Переключателя
  «Command right after wake word» тоже нет, но по другой причине: пре-ролл для Мини не измерен.
  Кольцо — 6 светодиодов.
- Кнопка отключения микрофонов переключает программный мут: состояние сохраняется на диск сразу и
  переживает перезапуск. Начать диалог с самой колонки можно только фразой «Алиса» / «Яндекс».
- Громкость программная (через HA, голосом или Sendspin), по той же кривой в дБ, что softvol
  остальных моделей: одна ступень 5 % — те же ~2,5 дБ, поэтому 6 % в HA звучат так же тихо, как на
  Миди.
- Код сопряжения Sendspin выводится только в журнал. USB-плеер и AirPlay-приёмник не
  поддерживаются.

## Мониторинг (Prometheus)

Демон отдаёт метрики в текстовом формате Prometheus:

```bash
curl -s http://<адрес-колонки>:9101/metrics
```

Порт — `9101` (базовый, как в `pulsar_metrics::DEFAULT_PORT`; `PULSAR_PORT_OFFSET`
сдвигает его вместе с остальными портами станции). Слушает `0.0.0.0`, без
авторизации и TLS: это LAN-эндпойнт для домашнего Prometheus, в интернет его
публиковать нельзя. Firewall на колонке не настраивается; если появится
входящий фильтр, разрешите `tcp/9101` только с адреса Prometheus.

Что экспортируется (все имена с префиксом `pulsar_`):

- **Железо** — загрузка CPU (из `/proc/stat`, доля за интервал между scrape),
  CPU-секунды по режимам, load average, температура SoC
  (`/sys/class/thermal/thermal_zone*/temp`), RAM total/available
  (`/proc/meminfo`), диск `/data` и `/` (`statvfs`), uptime.
- **Связь с HA** — `pulsar_ha_connected`, `pulsar_ha_reconnects_total`.
- **Ассистент** — `pulsar_assistant_requests_total{result="ok|error|timeout"}`,
  гистограммы `pulsar_assistant_wake_to_stt_seconds` (wake → начало STT) и
  `pulsar_assistant_wake_to_answer_seconds` (wake → начало проигрывания TTS;
  длительность самого ответа не входит — отсчёт останавливается до старта
  плеера, один замер на run).
- **Звук** — `pulsar_playback_started_total`/`_finished_total{kind,result}`,
  `pulsar_alsa_xruns_total`, `pulsar_mute{kind="hw|sw"}`, `pulsar_volume_ratio`.
- **Звонки** — `pulsar_call_active`, `pulsar_call_incoming_total`,
  `pulsar_call_ended_total`, гистограмма `pulsar_call_duration_seconds`,
  `pulsar_call_fec_total`, `pulsar_call_plc_total`,
  `pulsar_call_packets_lost_total`, `pulsar_call_underrun_total`,
  `pulsar_call_overflow_total`.
- **Wake-word** — `pulsar_wake_detections_total`, `pulsar_wake_near_total`
  (отклонено порогом), `pulsar_wake_miss_total`,
  `pulsar_wake_labels_total{label="false|missed"}`,
  гистограмма `pulsar_wake_score`, `pulsar_wake_threshold`,
  `pulsar_wake_model_info{model,version}`.

Счётчики и гистограммы — атомарные (`Relaxed`), аудиопоток и звонок в них не
блокируются и не аллоцируют. Полный каталог имён —
`satellite/crates/pulsar-metrics/src/catalog.rs`; тест
`projects/home/kubernetes/observability/test_prometheusrule.py` сверяет с ним
каждую метрику из правил и дашбордов.

Готовые дашборды («Колонка — железо», «Колонка — Pulsar») и алерты лежат в
`projects/station/observability/`; их ставит Flux в папку Grafana «Колонка».
Scrape-задание `station` в Prometheus описано в
`projects/home/kubernetes/observability/values/prometheus.yaml` и берёт адрес
из `${STATION_IP}`.

## Ограничения и риски

- Пока HA не записал ключ шифрования, API открыт без шифрования любому в сети: добавьте колонку в
  HA сразу после установки (или задайте ключ через `ctl.sh api-key`).
- Колонка по-прежнему использует DNS (`unbound`) и NTP прошивки, которые настроены на серверы
  Яндекса, и остаётся привязанной к аккаунту Яндекса.
- Обновления прошивки Яндекса pulsar не блокирует и не отслеживает: защита от OTA — задача
  владельца колонки и способа рута. Обновление прошивки может заменить системный раздел, и тогда
  пропадут автозапуск pulsar (`/etc/init.d/S99zpulsar`) и правки, сделанные способом рута.
  Автозапуск возвращается повторным запуском установщика, если root-доступ сохранился.
- Zigbee (экспериментально): порт 6638 без авторизации, install code и Green Power не
  поддерживаются, сеть Яндекса с устройствами Алисы pulsar не использует; роутером колонка входит в
  любую открытую сеть — см. [Zigbee](#zigbee-миди). На Лайт 2, Мини 2, Мини 3 и Мини Zigbee нет.
- SSH — вход под root без пароля, только в доверенной сети (см. [SSH](#ssh-необязательно)).
- Установщик для Windows и macOS не проверен на реальных компьютерах.
- Мини, Мини 2, Мини 3 — данные контрибьюторов; ограничения Мини — в разделе [Мини](#мини).
- Голос ответов — тот, что выбран в TTS Home Assistant; голоса Алисы нет.

## Заметки к коду

Пояснения, перенесённые из комментариев исходников (код комментариев не содержит, см. `AGENTS.md`).

- `.gitattributes` — Imported upstream tree: keep bytes exactly as upstream tracks them. Some fixtures and patches are CRLF, and golden tests compare exact content. The monorepo's core.autocrlf=input must not rewrite this subtree.
- `installer/src/adb.rs` — The device side of the installer: an `adb` process, or a fake in tests.
- `installer/src/cli.rs` — Command line: flags and the usage text. Behaviour is the Go installer's: unknown options and bad choices exit 1, `-h` prints the full usage on stdout and exits 0.
- `installer/src/console.rs` — Keeps a Windows console window that was opened for this process (double-click in Explorer) until Enter, so the output can be read. From a terminal the console is shared.
- `installer/src/deploy.rs` — Deployment: build the payload in a checkout, copy it to `/data/pulsar`, write the boot hook, migrate old `rootkeeper.sh` hooks and verify the restarted daemon.
  - Dropbear is installed by --ssh, in this run or an earlier one: never drop its autostart.
  - Whatever happened in between, / must not stay read-write.
  - Removes the hook lines older installers added to rootkeeper.sh (now in `INIT_PATH`), keeping a backup. Never creates or deletes the file: it belongs to the root method.
- `installer/src/deploy/tests.rs` — Golden tests for the deploy sequence: a fake `adb` records every call exactly like the Go generator did and replays the same answers. It can also return non-zero statuses with output (busybox `diff`, read-only rootfs, failed `ctl.sh`) to keep those paths covered.
- `installer/src/discover.rs` — Finding stations on the network: an mDNS query for Yandex announcements and the `--scan` /24 adb-port probe.
- `installer/src/lib.rs` — `pulsar-install`: finds rooted Yandex Stations on the local network and installs or updates pulsar.
- `installer/src/platformtools.rs` — Android SDK Platform-Tools: find `adb`, or download and unpack Google's archive.
  - Go's exec.LookPath: "." and empty entries do not search the current directory.
  - `filepath.IsLocal` after `filepath.Join` cleaning: a relative path whose `..` never escapes its base. `a/../b` is local, `../b` is not.
- `installer/src/probe.rs` — Model detection: the devicetree codename, the supported userspace ABI and the Mini's board-id + `quasar.cfg` pair. Must agree with `pulsar-model/src/detect.rs` and `satellite/deploy/boot.sh` (see docs/development.md, «Установка и станция»).
  - Userspace ABIs a model's firmware runs, its usual one first; empty = model not supported. The installed binary is build/<arch>/pulsar for the first ABI whose dynamic loader is on the station.
  - The model's first ABI whose loader is on the station (loaders: the words the loader probe printed). `""` = none of the model's ABIs: skip the station.
- `installer/src/scripts.rs` — Pure shell text the installer produces or inspects: the init script, the rootfs guard, `/proc/mounts` parsing and the old `rootkeeper.sh` hooks.
  - `""` if the root filesystem may be written, else the reason it must not be: dm-verity or any device-mapper target (writing under it corrupts the verified image), or /etc not on the filesystem mounted at / together with the firmware.
  - One device command, so the read-write window never spans two adb calls. The ignored HUP lets it finish if adb drops; the dot name keeps rcS's S??* glob from running a partial file. The subshell keeps exit from skipping `sh_raw`'s status echo.
  - The script is shared with other tooling and ends in an endless `while` loop: code after it never runs.
  - Whether `rk` starts pulsar: a hook line before the endless loop (code after it never runs).
- `publish-oci.sh` — Publish the station release as a public OCI artifact in GHCR with ORAS.
  - Verify every layer against the uploaded SHA256SUMS before publishing, so a broken artifact never reaches the registry.
- `radio/Makefile` — Zigbee firmware for the Midi's Telink B91 radio, from the Telink Zigbee SDK (Apache-2.0): router/ (a router in another network) and coordinator/ (network co-processor for pulsar's deCONZ server), both with common/ (board configuration, host-link pieces). Run through build.sh, which fetches the pinned SDK and toolchain and sets SDK / TC. Output: out/zigbee-router.ybl, out/zigbee-coordinator.ybl
- `radio/build.sh` — Builds the Zigbee firmware for the Station Midi's radio: radio/out/zigbee-coordinator.ybl and radio/out/zigbee-router.ybl. Fetches (once) the pinned Telink Zigbee SDK into radio/src/ and applies sdk.patch, and the Telink RISC-V toolchain (32-bit x86 Linux binaries: needs the i386 C library, e.g.
