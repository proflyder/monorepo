# quasar-root-kit

Автоматический набор для получения **root-доступа на своих Яндекс Станциях** (прошивка quasar: Лайт 2, Миди, Лайт 1; по механике должен подходить и остальным quasar-семейством 2023–2026) — в своей домашней сети, на своих устройствах.

> Используй только на **своих** устройствах и в **своей** сети. Получение root — твой осознанный выбор; автор не отвечает за кирпичи, потерю гарантии и недовольную Алису.
>
> Идея вектора (локальный прокси + статическая DNS-запись + серты из eMudhra-набора) — не наша: см. [eQuasar](https://git.gay/iwakura/eQuasar) (nginx-вариант). Этот набор — самодостаточная альтернатива со своим прокси-сервером на python, правилами на лету, мастером, защитой рута и блокировкой OTA.

## Что это

- `station-root.sh` — интерактивное меню (мастер ведёт до конца: серты → DNS-запись на твоём роутере → локальный прокси → root → защита от снятия → блокировка OTA → статус).
- `server.py` — локальный прозрачный HTTPS-прокси для `quasar.yandex.net` (порт 443): проброс в настоящий бэкенд + точечные правки ответов по правилам из `rules.json` (меняются на ходу, без рестарта).
- `rules.json` — правила: включение сетевого ADB (`adbd.remoteActivation=true`) и щит от обновлений (`check_updates_mode=block`).
- После root — по желанию — **fortress** (обёртка: `deactivate` → no-op + сторож rootkeeper) и **запрет OTA** (no-op в `device_ota_update.sh` + подмена ключа подписи `ota_script.pub` + `updatesd` вырезается из `launch.json`): рут и защита переживают ребут и живут на самой колонке, стенд больше не нужен.

## Требования

Linux + `python3 openssl dig curl avahi-utils sudo` (Debian/Ubuntu: `sudo apt install python3 openssl dnsutils curl avahi-utils`). adb скачивается автоматически (platform-tools), если его нет рядом.

## Серты

В Git есть `chain.pem` (лист `quasar.yandex.net` + промежуточный);
`leaf.key` нужен отдельно. В локальном стенде он хранится под
`secrets/local/projects/station/tools/quasar-root-kit/leaf.key` от корня
репозитория, рядом со скриптом — игнорируемая ссылка. Чистый checkout
не включает приватный ключ. Источник сертов — публичный набор из [eQuasar](https://git.gay/iwakura/eQuasar) (thanks [bitracker](https://blahaj.digital) & co): eMudhra → кросс от публичного корня AAA Certificate Services, который уже есть в траст-сторе колонок. Лист действует до **2029-01-22**; SAN покрывает `quasar.yandex.net/.ru`, `scbh`, и другие.

`leaf.key` — **секрет**: не коммить, не пересылай открыто. Если Яндекс отзовёт набор — колонки начнут отклонять TLS (в `mitm.log` будут отказы рукопожатия), набор продолжит работать только как DNS+прокси без включения ADB.

Проверка locally:

```bash
openssl x509 -in chain.pem -noout -subject -enddate
openssl x509 -in chain.pem -noout -pubkey | openssl sha256
openssl pkey -in leaf.key -pubout | openssl sha256          # хэши должны совпасть
openssl verify -CAfile roots/aaa_root.pem -untrusted chain.pem <(sed -n '1,/END CERT/p' chain.pem)
```

## Быстрый старт

```bash
./station-root.sh            # меню (Enter = Мастер)
# дальше мастер сам: покажет команду DNS-записи под ТВОЙ роутер
# (Keenetic/MikroTik/OpenWrt/pi-hole/dnsmasq — ставить будешь руками),
# поднимет прокси (sudo), попросит перегрузить колонку питанием,
# дождётся :5555 и выведет root-шелл; затем предложит защиту и статус.
```

Аргументы (для скриптов): `--run --status --fortress --fortress-off --ota-off --ota-on --backup --export --shell --router-off --ota-shield --help`. Колонку можно задать явно: `COLUMN_IP=<ip> ./station-root.sh --status`.

## Как это работает (коротко)

1. На роутере — статическая DNS-запись `quasar.yandex.net → этот ПК` (голос/uniproxy не трогаем). Роутеры у всех разные — скрипт печатает команды, ставить не лезет.
2. syncd колонки ходит в наш локальный прокси; в ответ `/get_sync_info` дописывается `adbd.remoteActivation=true (+network)`; maind (AdbSwitcher) запускает штатный `activate_adb.sh --quasmodrom activate --network`, маркеры в `/data/quasar/` переживают ребут.
3. `adb connect <колонка>:5555` — root-шелл (adbd в этом семействе стартует от root и без авторизации — **не открывай порт наружу**).
4. Защита: обёртки на ro-rootfs + сторож в rw-разделе `/data` → Яндекс не может ни снять adbd конфигом, ни обновить прошивку по OTA.
5. Снять DNS-запись и погасить прокси: рут и защита живут на колонке.

## Безопасность

- Прокси видит трафик syncd (в т.ч. OAuth-токен колонки) в `mitm.log` — **не публикуй логи**.
- `leaf.key` — секретный ключ: не выкладывай, не коммить.
- adbd (`:5555`) отдаёт root без пароля всем в LAN — домашняя сеть или VLAN, не общественный Wi-Fi.
- Полный сброс кнопкой сносит `/data` (маркеры, сторож) — рут снимается; повторяется с начала.
- OTA-обновления Яндекс не сможет доставить, пока стоит запрет: снимается `--ota-on` (сначала `--fortress-off`).
