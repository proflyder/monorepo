# Локальный сбор голоса для Ricardo

Временный инструмент: веб-интерфейс на Mac, микрофоны станции, WAV и JSON
только в приватной папке Mac. Он не обучает и не заменяет модель.

## Режимы и границы

Обычный режим не меняется до нажатия «Включить режим записи» и отметки
согласия. На время сеанса Pulsar останавливается корректным SIGTERM, его
существующие supervisor-процессы приостанавливаются SIGSTOP. Самостоятельный
`ricardo-voicestream` читает тот же `pulsar-audio` / VQE_OMNI_WITH_GAIN:
16 кГц, mono, PCM S16LE. Детекция wake/локальных команд выключена; HA
контроллера в процессе нет. Первый ~1 с VQE пропускается.

**Во время сеанса недоступны голосовой ассистент, музыка и другие функции
Pulsar.** Физический mute не включать: он может выключить сами микрофоны.
После завершения supervisor получает SIGCONT и запускает прежний Pulsar.
Это не замена бинарника: `pulsar`, `state.conf`, Noise/Sendspin keys,
`enabled`, init scripts, HA, сеть и авторизация SSH инструментом не меняются.
Сам штатный Pulsar может сохранить свои настройки при корректном выходе.
Внешние события/воспроизведение в паузе не гарантированно восстанавливаются:
лучше начинать запись при остановленной музыке и отсутствии будильника.

Поток идёт бинарно по SSH **без PTY**, с проверкой известного host key.
Прошивочный ADB имеет только PTY и для бинарного потока непригоден;
он используется только для копирования временного helper в `/tmp`.
Новые порты на станции, ключи, службы и автозапуск не создаются.

## Подготовка

Нужен актуальный игнорируемый checkout `projects/station/upstream/pulsar-rust`,
Rust/cargo-zigbuild, ARM target и Zig 0.14.1. Отдельный Cargo package
ссылается на его audio/core crates; сам checkout не редактируется.

```sh
.venv/bin/pip install -r projects/station/tools/voice-recorder/requirements.txt
# Только если Zig ещё не установлен:
.venv/bin/pip install ziglang==0.14.1
projects/station/tools/voice-recorder/build-helper.sh
```

Другой Zig: `ZIG=/path/to/zig .../build-helper.sh`. Бинарник и target cache
остаются в `secrets/local-tools/voice-recorder-target/`. Версии зависимостей
helper закреплены в Cargo.lock. Сборка armhf; для других моделей ABI
необходимо отдельно проверить до запуска.

Создайте приватный `secrets/voice-recorder/connection.json` (chmod 600):

```json
{
  "station": "192.0.2.13:5555",
  "ssh_target": "root@192.0.2.13",
  "ssh_key": "~/.ssh/station_ed25519",
  "port": 8765
}
```

Подставьте реальные локальные адреса вне Git. Если действующий SSH настроен
по паролю, вместо `ssh_key` задайте `credentials` с абсолютным путём к
локальному `secrets/CREDENTIALS.md`: читается поле таблицы `SSH-пароль`.
Пароль не копируется в конфигурацию, subprocess arguments, браузер или код.
Незнакомый/изменившийся SSH host key отклоняется; не отключайте эту проверку.
Ключи и настройки доступа инструмент не устанавливает.

## Пользование

1. Двойной щелчок по `start.command` или запуск его из Terminal.
2. Откройте `http://127.0.0.1:8765`. Начало работы сервера ничего не
   переключает на станции. Не запускайте несколько экземпляров инструмента.
3. Остановите музыку, убедитесь, что сейчас не требуется будильник/ассистент.
   Отметьте согласие и включите режим записи. Дождитесь живого уровня звука.
4. Выберите «Обучение», блок и заметку о расстоянии/обстановке. Начните дубль,
   подождите секунду и произнесите 10–15 примеров с паузами 2–3 с.
   Нажмите «Сохранить дубль». Название блока произносить не требуется.
5. Продолжайте с другими блоками. Голосовой дубль — максимум 3 минуты,
   фоновый — максимум 8 минут (но не дольше остатка сеанса);
   один сеанс — максимум ~9½ минут. Для продолжения создайте новый сеанс.
6. Нажмите «Завершить сеанс и вернуть ассистента», дождитесь подтверждения
   запуска Pulsar. Теперь можно прослушать WAV. Неудачные дубли исключаются
   обратимо, оригиналы остаются. Прослушивайте в наушниках; не воспроизводите
   примеры через колонку, чтобы снова не вызвать ассистента.
7. Проверочный набор запишите в другой сеанс позже и выберите «Проверка».
   Не используйте один и тот же дубль для обучения и оценки.

Рекомендуемый первый проход: 30 обычных, 30 расслабленных, 20 тихих,
20 шёпотом и 40 обращений с командами, в нескольких сеансах. Начните с
одного короткого дубля и проверки звука. Фон без wake word и конкретные
ложные срабатывания нужны отдельно. Колонка в этом режиме не воспроизводит
музыку сама: для примеров телевизора/музыки используйте внешний источник.
Сбор звука при собственном Sendspin-воспроизведении потребует иного режима.

Каждый дубль: отдельный WAV + JSON (блок, train/test, сеанс, заметка,
число кадров, peak, длительность, SHA256, прерывание и исключение).
По умолчанию: `secrets/voice-recorder/recordings/`. Нет автоматической
нормализации, удаления шума, нарезки по тишине или выгрузки в облако.
Запись после VQE подходит для детектора, но не позволяет восстановить
исходные микрофонные каналы или диагностировать потерянный VQE шёпот.

## Защита от обрыва и восстановление

- Страница подтверждает активность; без неё ~10 с локальный сервер
  останавливает сеанс. Закрытие страницы также отправляет stop.
- Самостоятельный watchdog на станции проверяет heartbeat раз в 2 с.
  Потеря heartbeat ~12 с: убить только наш helper и возобновить только
  прежние supervisor PID с проверкой cmdline.
- Вне зависимости от соединения helper имеет лимит 600 с. Watchdog
  также имеет независимый предел 600 с. Shell EXIT/HUP/INT/TERM trap
  возвращает supervisor. Это не гарантия при отказе питания/ядра/накопителя.
- Stop сохраняет завершённый дубль; при обрыве текущий дубль помечается
  interrupted. После принудительного убийства самого сервера WAV может
  остаться с незавершённым заголовком: такие файлы без JSON в список не входят.

Если интерфейс не подтвердил восстановление, сначала проверьте связь.
Явное восстановление **только этой интеграции**:

```sh
projects/station/tools/voice-recorder/start.command --recover-device
```

Оно останавливает наш helper и возобновляет сохранённые supervisor PID.
Если они уже отсутствуют, диагностику и восстановление штатного Pulsar
проводить по `docs/OPERATIONS.md`; автоматически включать другой стек нельзя.

## Полное удаление

1. Завершите сеанс и убедитесь, что Pulsar запущен.
2. Выполните `start.command --remove-device`: удаляется исключительно
   `/tmp/ricardo-voice-recorder/`; при активном lock удаление запрещено.
   Ключи, конфигурация и сервисы станции не затрагиваются.
3. Остановите локальный сервер Ctrl+C. Автозапуска на Mac нет.
4. Исходники можно удалить целиком из `projects/station/tools/voice-recorder/`;
   убрать его строку из агрегатора тестов и ссылку из tools/README.md. Игнорируемые записи и кэш под
   `secrets/voice-recorder/` / `secrets/local-tools/voice-recorder-target/`
   удалять отдельно только после решения, что они больше не нужны.

При перезагрузке станции `/tmp` очищается и запускается обычный штатный
Pulsar. Никакого startup-флага режима записи не создаётся.

## Проверки

```sh
.venv/bin/python -m unittest discover -s projects/station/tools/voice-recorder -p 'test_*.py' -v
node --check projects/station/tools/voice-recorder/web/app.js
sh -n projects/station/tools/voice-recorder/session.sh
sh -n projects/station/tools/voice-recorder/recover.sh
```

Не запускать live запись как hermetic-тест. Voice recordings/connection
config/диагностика не должны попадать в Git или публичный отчёт.
